AI System Design 02：Planner 与 Action —— AI 如何制定计划并开始行动

本章回答的问题：
当 Router 完成任务路由之后，AI 是如何制定计划，并一步一步完成整个任务的？

课程位置：

Router → Planner → Action（本章） → Tool → Observation → Memory

本章目标

完成本章学习后，你应该能够回答以下几个问题：

  • Planner 是什么？
  • 为什么 AI 系统需要 Planner？
  • Action 是什么？
  • Planner 与 Action 是什么关系？
  • Action 与 Tool 有什么区别？

一、Planner：负责维护整个执行计划

Planner（规划器）的职责是：

根据当前目标和已有信息，持续决定下一步应该执行什么动作。

需要注意的是，Planner 并不是一次性生成一份完整计划，而是在执行过程中不断根据新的结果调整后续步骤，因此它更接近”持续规划”而不是”一次规划”。

二、为什么需要 Planner

对于简单问题，大模型可以直接回答。

但在真实 Agent 系统中，很多任务都需要经过多个步骤才能完成，例如：

  • 阅读项目代码
  • 查找相关文档
  • 搜索资料
  • 调用工具
  • 汇总结果

这些步骤通常无法在任务开始时全部确定，因此需要 Planner 在执行过程中不断更新计划。

三、Action：当前立即执行的一步

Action 表示：

Planner 当前决定立即执行的一项具体动作。

例如：

  • Read README
  • Search Code
  • Read Log
  • Search Web
  • Run Test

可以理解为：Planner 负责整体规划，而 Action 是当前真正开始执行的那一步。

四、Planner 与 Action 的关系

Goal
  │
  ▼
Planner（维护整个计划）
  │
  ├── Action 1
  ├── Action 2
  ├── Action 3
  └── ...

整个任务只有一个 Planner，但在任务执行过程中会不断产生新的 Action。

Planner 决定”下一步是什么”，Action 表示”下一步具体做什么”。

五、Action 与 Tool 的区别

这是初学 Agent 时最容易混淆的概念之一。

Action 表示：

要做什么。

例如：

  • Read File
  • Search Web

Tool 表示：

使用什么能力完成这一步。

例如：

  • Filesystem
  • Browser
  • Search API

因此：

  • Action 描述的是动作。
  • Tool 描述的是执行动作所使用的能力。

下一章将重点介绍 Tool 与 Observation。

六、目前完整的执行流程

截至目前，我们已经学习了系统中的前几个核心组件：

User
  ↓
Router
  ↓
Planner
  ↓
Action
  ↓
（下一章）
Tool
  ↓
Observation

随着课程继续推进，这条流程会逐步补充完整。

本章总结

  • Router 完成任务路由后，Planner 开始工作。
  • Planner 负责维护整个执行计划，而不是生成固定流程。
  • Action 是 Planner 当前决定执行的一项具体动作。
  • 一个 Planner 会产生多个 Action。
  • Action 与 Tool 分别回答”做什么”和”用什么做”两个不同的问题。

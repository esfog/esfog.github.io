# AI System Design 01：现代 AI 产品全景图与 Router

> 从「使用 AI」到「设计 AI」的第一课

------------------------------------------------------------------------

## 本文目标

阅读完本文后，希望能够回答下面几个问题：

-   什么是 AI System Design？
-   Router 和 Planner 的职责分别是什么？
-   为什么 Router、Planner 和 LLM 不属于同一个层次？
-   一个现代 AI 产品的大致执行流程是什么？

------------------------------------------------------------------------

## 一、本课程研究什么？

本课程研究的不是：

> 某个大模型（GPT、Claude、Gemini、Qwen 等）是如何训练出来的。

而是：

> **现代 AI 产品（ChatGPT、Cursor、Codex、Claude Code
> 等）是如何组织多个模块协同完成任务的。**

因此，本课程讨论的是 **AI System Design（AI 系统设计）**，而不是
Transformer 算法本身。

## 二、核心概念

### 职责（Responsibility）

系统中负责完成某一类工作的角色。

例如：

-   Router
-   Planner
-   Memory
-   Tool Manager

### 实现（Implementation）

完成这些职责所采用的技术。

例如：

-   GPT-5
-   Claude
-   Qwen
-   DeepSeek

> 一个实现可以承担多个职责；一个职责也可以由不同实现完成。

> 这是逻辑架构（Logical Architecture），不是部署架构（Deployment
> Architecture）。

------------------------------------------------------------------------

## 四、Router

一句话总结：

> **Router 决定任务进入哪条处理路径。**

主要职责：

-   判断任务类型
-   选择 Workflow
-   选择 Agent
-   决定启用哪些工具
-   决定是否读取上下文
-   决定模型策略

> Router 更关心 **任务交给谁**，而不是 **任务如何完成**。

------------------------------------------------------------------------

## 五、Planner

一句话总结：

> **Planner 决定如何完成已经确定的任务。**

典型流程：

``` text
读取日志
↓
分析错误
↓
定位代码
↓
修改
↓
测试
↓
继续修复
```

Planner 负责：

-   制定执行步骤
-   调整执行步骤
-   根据结果重新规划
-   控制整个执行流程

Planner 的输出通常不是最终答案，而是一系列待执行的 Action，例如：

1.  Read Log
2.  Search Code
3.  Read File
4.  Edit File
5.  Run Test

------------------------------------------------------------------------

## 六、Hypothesis（假设）与 Evidence（证据）

现代 AI 的推理过程，本质上是：

> **提出假设（Hypothesis）→ 收集证据（Evidence）→ 验证假设 →
> 修正假设。**

例如：

用户：**登录失败**

可能产生多个 Hypothesis：

-   Authentication
-   Token
-   Network
-   Server
-   UI

随后 Tool 收集：

-   Log
-   Stack Trace
-   Code
-   Config
-   HTTP Response

LLM 根据这些证据不断修正判断。

> 收集信息不是目的，验证假设才是目的。

注意：

Hypothesis 是一种通用推理概念，不仅用于 Bug
修复，也适用于写作、规划、分析等任务。

------------------------------------------------------------------------

## 七、Router、Planner 与 LLM 的关系

``` text
Router
↓
Planner
↓
LLM 推理
↓
Tool 获取信息
↓
LLM 更新判断
↓
Planner 决定下一步
↓
……
```

需要强调：

-   Router 一般不会提出具体假设。
-   Planner 组织执行流程。
-   LLM 在执行过程中提出、验证和修正假设。

------------------------------------------------------------------------

## 八、本章小结

1.  现代 AI 产品是一套系统，LLM 只是其中一个核心组件。
2.  Router 与 Planner 描述的是职责，LLM 描述的是实现。
3.  AI 的能力来自：**正确获取信息 + 正确推理 + 正确执行。**

------------------------------------------------------------------------

## 九、思维方式的改变

以后分析任何 AI 产品时，不要先问：

> 它用了什么模型？

而应该先问：

1.  Router 如何决定任务流向？
2.  Planner 如何组织执行？
3.  Tool 如何获取信息？
4.  LLM 如何完成推理？

这是从「使用 AI」走向「设计 AI」的重要思维转变。
